# План скриншотов для README

Скриншоты должны показывать реальный Voople, а не обещанный интерфейс. Перед
съёмкой уберите личные данные, тестовые ошибки, devtools, курсор, системные
уведомления и случайные обрезанные popover.

## Общий стиль shots.so

- Один визуальный пресет для всей серии: тёмный фиолетово-графитовый фон,
  мягкая тень, одинаковый радиус окна и 56–72 px воздуха вокруг.
- Не добавлять макет браузера к desktop-клиенту. Для web использовать очень
  тонкий browser chrome либо только viewport — но одинаково во всей web-серии.
- Сохранять исходный масштаб интерфейса; не растягивать узкий кадр на 16:9.
- Экспортировать WebP без агрессивного размытия текста.
- Подпись в shots.so — короткая строка из плана ниже, без второго абзаца и
  технических терминов.

## Обязательные кадры

| Файл | Что снять | Состояние | Подпись |
| --- | --- | --- | --- |
| `01-home.webp` | Desktop Главная целиком | rail compact, «Сейчас» раскрыт, есть 2–3 нормальных поста и полезный right rail | «Те, с кем хочется быть на связи» |
| `02-chat-room.webp` | Групповой чат | видны разделы, одно содержательное сообщение, compact actions и активная комната; без длинной истории системных событий | «Один разговор — от сообщения до комнаты» |
| `03-screen-share.webp` | Комната с демонстрацией приложения | минимум два участника, кадр полностью помещается, controls не перекрывают видео, sender self-preview не выбран автоматически | «Показывайте, объясняйте, смотрите вместе» |
| `04-profile.webp` | Полный профиль | двухколоночный layout, согласованные баннер/аватар/рамка/тег, mini-profile не открыт поверх основного кадра | «Профиль, который действительно ваш» |

## Финальная проверка

Перед заменой placeholder в `README.md` проверить тёмную тему, отсутствие
горизонтального overflow, корректные tooltips/popover boundaries и совпадение
кадра web/desktop с актуальной production-сборкой.
