# Voople: спецификация IA и состояний интерфейса

## 1. Статус и решения

Это предложенная единая спецификация реализации после rework. Все размеры и взаимодействия ниже — **решения**, а не результаты пользовательского теста. Принятые продуктовые инварианты сохранены. Изменения относительно canonical sources перечислены явно в §3; существующие планы и приложение этим документом автоматически не переписаны.

Область: web, desktop и responsive messaging/live от 360 CSS px. Native mobile использует те же domain contracts, но требует отдельной проверки устройств. Режим интерфейса — Operate: читать, писать, видеть доступный разговор, подключаться и продолжать работу.

### Зафиксированная модель

1. Один global sidebar на desktop. Он содержит Groups, DMs, Search и current user.
2. Group открывает Chat. `Чат / Войс / Люди` — взаимоисключающие views. `Войс` — пользовательское название Group live overview; внутренний id `now` сохраняется.
3. Group Chat — постоянный текстовый контекст группы с необязательными Sections. Room не владеет сообщениями.
4. Активный live появляется над Chat в ограниченном по высоте Live Shelf. Пустой Shelf отсутствует.
5. `Зайти` открывает Full Room **вместо main content area**, оставляя global sidebar.
6. Full Room имеет один локальный Room Switcher. Его присутствие зависит от полезной ширины stage.
7. Кнопка `Чат` в Full Room показывает обычный Group Chat в contextual drawer. По умолчанию без фильтра по Room/LiveSession.
8. Навигация в другую Group, DM, Search или Profile сворачивает сессию в Mini Room. Она не переключает сам разговор.
9. Максимум одна активная live-сессия на пользователя, включая другие устройства. Сервер — источник истины.
10. Room Guest видит только разрешённую ему Room; полный Group Chat ему не открывается.
11. Лобби — постоянный общий разговор группы, выделенный среди дополнительных комнат. Открыть группу означает увидеть общий контекст; явное действие входа в голос без выбранной комнаты ведёт прямо в Лобби. Автоматического подключения к звуку при навигации нет. Подробный контракт — §9.

### Сквозной принцип: действие без промежуточного экрана

Уточнение после требования о максимально простом, лёгком и быстром UX. Применяется ко всему приложению, включая secondary surfaces. Обычное действие выполняется непосредственно из текущего контекста. Короткое редактирование происходит на месте. Сведения открываются в одном contextual panel. Большие настройки имеют собственную страницу. Модальное подтверждение допустимо только при существенном последствии, требующем отдельного согласия, или когда его требует ОС/браузер.

Не заменять каждую старую modal механически на drawer: ненужный шаг нужно удалить. Никаких цепочек `modal → form → confirmation → success modal`. Успех отражается новым состоянием самого интерфейса; ошибка и retry находятся рядом с действием. Нельзя показывать весь экран loading, если изменяется одна строка. Обратимые действия выполняются без подтверждения; undo использовать там, где оно действительно поддерживается сервером.

| Действие | Минимальный путь | Поверхность |
| --- | --- | --- |
| Войти в существующую Room/Lobby | Один click «Зайти» | Сразу Full Room в main, connecting внутри; без промежуточного Voople prejoin dialog |
| Создать временную Room | Один click `+ Комната` = создать и войти | Сразу конечная Room surface; имя по умолчанию, optional inline rename после входа |
| Назвать/переименовать Room | Click имени → текст → Enter | Inline field; Escape отменяет правку, ошибка под полем |
| Закрепить Room | Action «Закрепить» при наличии права | Обновляется marker; без создания ещё одной Room и без подтверждения |
| Сменить Room внутри Group | Один click цели | Pending в текущей поверхности, затем actual placement; без нового setup |
| Открыть Chat во время Room | Один click «Чат» | Один contextual panel; закрытие возвращает stage |
| Пригласить по ссылке | Click «Пригласить» → «Скопировать ссылку» | Небольшой anchored popover; success прямо у кнопки |
| Пригласить конкретных людей | Тот же popover: поиск/выбор → отправить | Без отдельного wizard и финального success dialog |
| Сменить mic/output | Открыть device menu → выбрать | Anchored popover; полные audio settings только по отдельной ссылке |
| Создать Section | Selector → `Создать` → имя → Enter | Inline row внутри текущего selector, без второй modal |
| Открыть профиль/Group Info/media | Click соответствующего действия | Один contextual panel; большая поверхность — отдельный route |
| Создать Group / изменить большие настройки | Прямой переход к короткой форме | Main-area page с сохранением контекста возврата; optional настройки после создания |
| Прикрепить файл / включить screen share | Сразу platform picker из исходной кнопки | Системный chooser допустим; перед ним нет дополнительного welcome/confirm dialog |
| Перейти в другой voice context | Одно короткое объяснение последствия → подтвердить | Предпочтительно inline в точке действия; текущая сессия продолжается до согласия |
| Выйти из своего разговора | Один click leave | Сразу local stop + server reconciliation; без «Вы уверены?» |
| Удалить данные / завершить разговор всем | Явное подтверждение конкретного последствия | Inline confirm либо один dialog; без вложенных подтверждений |

**Создание Room.** Default — temporary с именем «Новая комната», нормализованным существующими правилами имён; если контракт требует уникальности, имя выбирается сервером. Никаких обязательных полей icon/type/privacy/capacity перед первым разговором. Имя меняется на месте в Full Room, pinned применяется отдельным действием при правах. Создание и join используют существующую атомарную операцию и один request ID. Повторный click не создаёт дубль. При cancel во время pending согласовать поздний ответ и компенсировать участие; пустую temporary Room завершает существующий lifecycle. Если уже идёт разговор в другой Group/DM, предупреждение предшествует mutation: отмена не оставляет созданную Room.

**Первый вход.** Отдельный product prejoin экран не обязателен. Разрешение микрофона запрашивает платформа после явного Join; запрос, denied/retry и выбор устройства отображаются внутри конечной Room surface. При доступной возможности разрешить слушать без микрофона. После platform permission не просить повторно нажать «Зайти». Guest nickname вводится на уже открытом invite preview; отдельное окно регистрации перед участием не появляется.

**Mobile.** Маленький anchored picker может стать одним bottom sheet с теми же действиями. Это адаптация списка к touch, а не дополнительный шаг. Sheet не открывает поверх себя следующий sheet: inline ввод заменяет его содержимое с понятным Back. При переходе на основную поверхность picker закрывается автоматически.

**Бюджет взаимодействия.** Join, same-group switch, temporary create-and-join, mute и leave — одно осознанное действие при готовых разрешениях и доступе. Действие даёт локальную визуальную реакцию сразу; animation не задерживает mutation. Сеть, permission, авторизация и recovery остаются реальными состояниями, а не маскируются ложным успехом. При смене views сохраняются draft, scroll, selected Section, session и осмысленный focus. Эти правила проверять одинаково в web/desktop/mobile.

`voople_ref_rework` — moodboard нескольких состояний, не один screenshot приложения. Сохранить плотность, graphite, тонкие разделители, выразительные avatar tokens, локальный switcher и крупный shared content. Удалить из буквального переноса Global Now, гигантское создание Room, декоративные подсказки, постоянный cockpit и набор из пяти профилей.

`other_ref1` полезен общей структурой Chat + live. ## 4. FINAL IA TREE

```text
App shell
├─ Global navigation [desktop sidebar / mobile Chats index]
│  ├─ Groups [+ создать]
│  │  └─ Group
│  │     ├─ Чат [default]
│  │     │  ├─ Live Shelf [только при live]
│  │     │  ├─ Section selector [если sections > 1]
│  │     │  ├─ Message stream
│  │     │  └─ Composer
│  │     ├─ Сейчас [rooms → online outside → empty pinned]
│  │     ├─ Люди [сейчас / online / остальные]
│  │     └─ Info / media / pins / search / events / settings [по действию]
│  ├─ DMs [+ новый диалог]
│  │  └─ DM [history + composer + call]
│  ├─ Search [messages / people / groups / secondary content]
│  └─ Current user
│     ├─ Profile [реальный identity + content skeleton]
│     ├─ Saved Messages [если capability доступна]
│     ├─ Settings / notifications / privacy / security
│     ├─ Store / Voople+ / cosmetics
│     └─ Help / account actions
├─ Main viewport [ровно одна основная поверхность]
│  ├─ выбранный Group view / DM / Search / Profile / secondary route
│  └─ Full Room OR Full DM Call
│     ├─ Local Room Switcher [только Group; по ширине]
│     ├─ Header + stage + controls
│     └─ Context panel [chat OR details; максимум один]
├─ Persistent session host [переживает смену routes]
│  └─ Mini Room [когда активная сессия не показана Full]
├─ Activity inbox [по действию, без постоянной колонки]
└─ Guest entry [ограниченный public shell]
   ├─ Invite preview / permissions / join
   ├─ Guest Full/Mini Room [в рамках разрешённого browser flow]
   └─ Explicit account conversion
```

Notifications не смешиваются с Search и не требуют отдельного sidebar пункта. Compact activity button расположен в header; на mobile Chats index — в его header. Posts находятся в Profile и secondary Search. Public discovery не открывается по умолчанию. Settings может иметь собственную локальную навигацию; она не превращается в второй global sidebar.

### Правило полезной ширины Full Room

`B = ширина main после global sidebar`. Для split-chat минимальная media stage width — 640 px. Это порог переключения layout, не минимальный размер приложения.

1. Если `B >= 1160`, доступны switcher 160 + stage ≥640 + drawer 360.
2. Если `1000 <= B < 1160`, при открытии drawer switcher уходит в dropdown; stage остаётся ≥640.
3. Если `B < 1000`, Chat открывается поверх main как один contextual panel. Stage под ним не становится узкой колонкой; media connection сохраняется.
4. Без drawer локальный switcher показывается при `B >= 800`; иначе это selector в header.
5. При ручном расширении drawer применяются те же пороги; width clamp не позволяет нарушить stage budget.

| Viewport | Практический layout |
| --- | --- |
| 1920 | Sidebar 216; wide stage; Chat split; switcher виден; message stream ограничен max-width |
| 1440 | Sidebar 216; B=1224; switcher 160 + drawer 360 оставляют stage 704 |
| 1280 | Sidebar 216; B=1064; Chat split, switcher dropdown; stage 704 |
| 1024 | Sidebar 200; B=824; без Chat switcher виден, с Chat — overlay panel |
| 768–1023 | Sidebar 200 или ручной compact 64; по B switcher/dropdown и overlay |
| 360–767 | Sidebar заменён Chats index; одна основная поверхность; full-width Chat panel в live |

При 125–200% zoom решения применяются к фактически доступным CSS px. Не определять mobile исключительно user agent. Native titlebar drag-region не перекрывает controls; fullscreen работает в рамках платформенного adapter.

### Design language и доступность

Void: near-black graphite canvas, чуть более светлая graphite surface, тёплый off-white текст. Light: тёплый светлый canvas, белая/светло-серая surface, тёмный graphite текст. Те же уровни и геометрия в обеих темах. Существующие `--background`, `--foreground`, `--app-surface`, `--app-surface-soft`, `--app-border`, `--app-muted`, `--theme-accent` назначаются на эти роли; page-specific hex colors не вводить.

Violet — selected, primary, focus; green — online/live; red — leave/destructive/error. Border 1 px, радиусы 3–6 px, до 8 только для особых shared primitives. Заливка сообщения не меняется по признаку «моё». Без gradients, glass, decorative waveform и ambient neon. Один clean grotesk для UI, mono только для компактного времени/технических показателей; системные headings не превращать в широкие uppercase labels.

Минимальная целевая контрастность: обычный текст 4.5:1, значимые границы controls/focus 3:1. Цвет всегда дополняется text/icon/state. Pointer controls минимум 32 px, touch controls 44 px; glyph может быть меньше hit target. Shared tooltip появляется по hover и keyboard focus. Все popovers выходят из clipping scroll containers; раскрытие списка не меняет layout соседних кнопок.

Group tabs имеют tablist semantics; room selector не auto-activates при стрелках. Live updates не уводят focus и не переупорядочивают focused item. Screen reader получает connect/reconnect/leave сообщения, но не каждое изменение speaking waveform. Reduced motion отключает перемещения/пульсацию, сохраняя state marker. Escape закрывает верхний contextual слой; после fullscreen сначала возвращает обычную stage. Ни одна Escape-комбинация не является скрытым hang-up.

## 6. Global sidebar

Логотип сверху, далее Groups и DMs. Оба блока могут сворачиваться; одна общая scroll-area. Search и current user закреплены снизу. Groups и DMs имеют отдельный `+` с понятным accessible name. Unread counts — нейтральные/контрастные badges; violet — selected/focus. Green только про известный online/live state.

Строка группы: avatar, имя, под ним `3 в голосе · 2 комнаты` или `Нет активных разговоров` только если нужен status, отдельный unread badge. Не писать «3 говорят», когда сервер знает лишь membership session. Speaking signal означает фактическое локально наблюдаемое speaking состояние, без ложного обещания точности устаревшего snapshot.

Click по названию открывает Group Chat и восстановленный Section/scroll. Click по live badge открывает Group Сейчас. Hover mic — дополнительный shortcut Lobby; он также доступен через keyboard focus и context menu на touch. Никакое hover действие не выполняется само. Нажатие уже выбранной Group не завершает сессию и не закрывает переписку.

Не показывать room tree постоянно под Group. Это одновременно нагружает sidebar и дублирует Сейчас. При нескольких десятках DMs сохранять поиск и стабильные pinned items, остальное сортировать по последнему message activity. Live updates не переставляют группы под курсором.

## 7. Sections и Group Chat

### Семантика

Group Chat означает постоянный общий текстовый контекст группы. При включённых Sections сообщение отправляется в **один выбранный Section**, а не одновременно во все разделы. Root history — «Общий». Существующие child `chats` и их права остаются; единство UX не требует миграции всех сообщений в одну таблицу или полного снятия section permissions.

**Выбор selector:** текущий раздел + максимум два явно закреплённых пользователем shortcuts. Автоматические recent-tabs не используются: они меняют позиции во время чтения и дублируют current selection. Recent допускаются только внутри открытого selector, ниже unread/favorites.

```text
[Общий v  • 7 в других]  [Game 2]  [Мемы]          [Поиск] [Медиа] [...]
```

Если текущий Section входит в favorites, он не дублируется shortcut-ом. На узком месте shortcuts убираются, selector остаётся. Отдельной кнопки `Ещё` для тех же Sections нет: dropdown уже обозначает весь список. `...` справа — действия чата, не второй каталог разделов.

### Открытый selector

```text
Разделы VOICEKK
[Найти раздел...                       ]
Непрочитанное
  Game                         2   @1
  Фото                         5
Закреплённые
  Мемы                         ☆
Все разделы
  Общий                        ✓
  ... [алфавитный список; без дублей выше]
---------------------------------------
+ Создать раздел [если разрешено]
```

Popup 320 px, max-height 420; список scroll внутри. Для 30 sections — поиск по имени и description, unread count, keyboard navigation. Закрытые разделы, к которым нет доступа, не отображаются и не участвуют в counts. Первый matching item не выбирается без Enter/click.

| Сценарий | Поведение |
| --- | --- |
| Один доступный Section | Selector/shortcuts полностью скрыты. Search/media в header menu. Создание через меню группы |
| 2–3 Sections | Текущий dropdown + до двух favorites; никаких автосозданных tabs |
| 30 Sections | Тот же toolbar; поиск и группированный список; favorites не расширяют его высоту |
| Mouse | Click selector, click row; star — отдельная кнопка без смены раздела |
| Keyboard | Tab до selector, Enter/Space открыть, Up/Down/Home/End по options, typing в search, Enter выбрать, Escape вернуть focus |
| Direct section shortcut | Optional remappable `Alt+Shift+S`, только после проверки OS/browser conflicts; Tab-flow всегда основной |
| Unread | Count текущего рядом с именем; `в других` — агрегат остальных доступных; mention count отдельно внутри списка |
| Создание | Inline name внутри selector, Enter создаёт; icon можно настроить позже. Существующие server permission rules; pending/error на месте. Успех открывает новый Section |
| Архивирование выбранного | История по установленной policy; composer readonly, перейти в Общий явной ссылкой; draft не терять |

### Stream и отправка

```text
[avatar] nmggk · DRG · 23:41
         кинул скрин с сегодняшнего захода
         [image]
         [reaction 3] [reaction 2]
         ещё одно сообщение             23:42 [доставлено]
```

Автор один раз в блоке; последовательные сообщения одного автора с одинаковым Room snapshot группируются в пределах 5 минут. Смена Room/LiveSession, reply или существенный time gap начинает новый блок. Все сообщения слева; свои отмечаются авторством и delivery status. Reply preview — компактная цитата, attachment сохраняет собственный preview frame; у каждого текстового сообщения нет отдельной карточки.

Read state обновляется только для видимого focused Section и действительно просмотренного диапазона. Открытие группы не обнуляет все разделы. Draft key — account + conversation/section ID; drawer и main читают один draft store. Переключение Section не переносит написанное в другой адресат. Cursor/scroll восстановить после close drawer и после смены views.

Composer всегда явно подписывает адресата: `Сообщение VOICEKK · Game`. Room metadata назначает сервер при вставке по активной сессии той же Group. При отправке в другую Group или DM она не прикрепляется. Отложенная offline-отправка использует действующий серверный контекст при фактической записи; не утверждать, что сообщение отправлено из старой DRG, если сессия уже закончилась. Исходный offline draft и media upload сохраняются независимо.

### Шум системных событий

Join/leave/move не создают отдельные видимые сообщения каждому действию. Для группы одна дневная activity summary высотой около 24 px; соседние дни без обычных сообщений сворачиваются в одну строку периода с раскрытием. При раскрытии — внутренний список, без автоматической прокрутки чата. Существующие records не удалять и не менять retention ради визуального эффекта. DM call missed/completed остаются понятными отдельными событиями. Итоговые длительности — server-authoritative, их нельзя складывать на клиенте с двойным учётом параллельных sessions.

## 8. Live Shelf

Место: сразу под Group header, перед Section toolbar. Scope — вся Group, даже если открыт Section Game. Нет активных разговоров и есть свежие достоверные данные → Shelf отсутствует, включая пустой заголовок и рамку.

Одна активная Room: одна компактная строка, имя, до трёх аватаров, count, live/share signal, `Зайти`. При двух/трёх rooms и B≥1000 — 2/3 компактные ячейки в одной строке. Это flat cells с разделителями, не большие cards. При B<1000 — максимум две строки. Порядок стабилен: текущая Room первой, затем active Lobby, затем остальные по стабильному порядку комнаты. Speaking updates порядок не меняют.

При переполнении: последняя доступная позиция — `Ещё N разговоров`. Click открывает popover со **всеми оставшимися Room отдельно**, count/people/Join. Footer `Все разговоры → Войс`. Скрытой горизонтальной прокрутки нет. На mobile показывается одна Room + overflow; текущая Room имеет приоритет. Видимая суммарная информация не заменяет именованные строки внутри overflow. Lobby подписана `Лобби · Общий разговор`; это не ещё одна пользовательская комната. Ради этого различия Shelf не получает дополнительный ряд или большую карточку.

На коротком viewport H<640 Shelf автоматически использует компактный вариант около 52 px. Ручное `Свернуть` оставляет 32 px строку `Лобби 3 · DRG 2 · Ещё N`; действия Join доступны после раскрытия. Предпочтение per Group/device; новые комнаты обновляют overflow count, но не раскрывают Shelf самовольно.

Если данные ещё загружаются: одна нейтральная status строка «Проверяем разговоры», не фиктивные аватары. Если свежего snapshot нет из-за offline/error: не заявлять «никого нет»; `Live-статус недоступен · Повторить`. При reconnect старый snapshot помечен как устаревший, Join не притворяется мгновенно успешным.

`Зайти` означает реальное присоединение. Для собственной Room действие `Открыть` возвращает Full Room. Avatars открывают мини-профиль, не запускают voice. Нажатие share indicator даёт сведения о демонстрации; подписка на media — после разрешённого join, без скрытого guest доступа.

## 9. Group / Войс и Group / Люди

### Лобби как общее место компании

**Решение.** Группа — постоянный хаб: общий чат, люди и видимые разговоры. Лобби — её постоянное общее место для голосового общения. Комнаты — дополнительные места для отдельных разговоров. В интерфейсе Лобби выделено и не входит в число дополнительных комнат. Термин «хаб» объясняет модель здесь; новую вкладку или сущность «Хаб» в приложение не добавляем.

«Все уже сидят вместе» должно означать реальное участие: сразу видны те, кто действительно подключён к Лобби. Членство в группе, просмотр её чата и online presence не записывают человека в голосовой roster. Иначе нельзя понять, кто слышит разговор. Открытие группы показывает Chat + активный Shelf, без промежуточной landing page и без подключения к аудио, даже с выключенным микрофоном. Это также позволяет читать другую группу, продолжая текущий разговор.

**Прямой вход.** Если человек сам нажал голосовое действие группы, а конкретная комната не выбрана, подключаем прямо в Лобби: без выбора комнаты, modal или обязательного setup. В header остаётся одна компактная точка входа `Войти в Лобби` с доступным названием «Присоединиться к общему разговору группы». В блоке самого Лобби действие называется `Начать разговор`, если оно пусто, и `Присоединиться`, если там есть люди. На узком экране допустимо короткое `Зайти` с тем же полным accessible name. Это один и тот же join, а не разные сценарии. При неизвестном статусе не утверждать, что разговор пуст: нейтральное `Войти в Лобби` + состояние загрузки/ошибки.

Если пользователь уже участвует в разговоре, header показывает фактические Group/Room и действие `Открыть разговор`; повторного Join в текущую сессию нет. Явный переход в Лобби доступен в Shelf/Войс и локальном switcher. Выбор конкретной DRG или `+ Комната` ведёт сразу к цели, минуя Лобби. Общий разговор — удобный default, а не обязательная пересадка.

| Ситуация | Результат |
| --- | --- |
| Открыть приложение, Group или приглашение в Group | Видеть общий контекст; не подключаться к голосу автоматически |
| Нажать `Войти в Лобби` без текущего разговора | Один join в Lobby → Full в main; в пустом Лобби пользователь начинает разговор |
| Открыть DRG по ссылке | Показать указанную цель; явный Join ведёт сразу в DRG, без захода в Лобби |
| Уже в Лобби → выбрать DRG | Один атомарный switch; server ACK определяет фактическое место |
| Уже в DRG → `В Лобби` | Один switch в общий разговор; без подтверждения внутри той же Group |
| Уже в DRG → выйти из разговора | Прекратить участие; не подключать автоматически к Лобби |
| Уже в DRG → открыть Chat/Сейчас | Сохранить DRG и Mini; просмотр группы не переводит в Лобби |
| Звонок в другой Group/DM → явный вход в Лобби | Сначала короткое подтверждение смены voice context; отмена сохраняет текущий разговор |
| Комната закрыта, доступ отозван или пользователь исключён | Остановить/reconcile участие; не переносить звук в Лобби. Предложить отдельный вход только при актуальном праве |
| Refresh или reconnect действующего разговора | Восстановить разрешённую сервером текущую сессию по существующему контракту; не создавать новый вход в Лобби |

**Возврат и выход.** В Full дополнительной комнаты доступно `В Лобби`: в видимом switcher это его постоянная первая строка, а при скрытом switcher — прямое компактное действие в header, без обязательного открытия picker. На 360 px оно остаётся видимым; менее частые controls уходят в overflow. В самом Лобби возврат не показывается. Отдельная кнопка выхода останавливает участие в голосе и возвращает прежний browsed view. Не использовать «Выйти в Лобби» и крестик с неясным последствием. Сворачивание Full/Mini меняет представление, а не участие. При switch прежние правила camera/share сохраняются: публикация останавливается и не переносится новой аудитории автоматически.

**Представление и счётчики.** В Сейчас Лобби занимает отдельный компактный блок `Лобби · Общий разговор` перед секцией `Комнаты`. Не делать из него dashboard или второй полноценный экран внутри экрана. В локальном switcher оно закреплено над разделителем, даже когда пусто; меню pin/archive у него отсутствует. Пустое Лобби не занимает место в Chat Shelf: войти можно из header. В активном Shelf остаётся приоритет текущего разговора, затем Лобби; никаких перестановок от speaking updates.

`Комнаты · N` считает только отображаемые дополнительные комнаты соответствующей секции; пустые pinned имеют свой счётчик. `N разговоров` считает занятые Лобби и дополнительные комнаты. `N в голосе` — реальные участники разрешённых сервером roster, включая явно помеченных гостей, если контракт допускает их показ. `N участников группы` — membership; `N в сети` — отдельный presence. Например, трое в Лобби и двое в DRG: `5 в голосе · 2 разговора`, ниже `Комнаты · 1`. Online человек вне голоса в эти пять не входит. Скрытые или недоступные roster не раскрываются через счётчики.

**Архитектура.** Сохраняется ровно одна постоянная Lobby на Group в существующей Room-модели и обычный LiveSession lifecycle. Постоянно существует место, а не бесконечная медиасессия. Пустая сессия завершается; Лобби остаётся. Отдельные Hub, LobbyParticipant, второй audio provider, автоматическая подписка всех online и новая история сообщений не нужны. Лобби нельзя удалить или архивировать; общий чат остаётся Group/Section Chat. Guest invite продолжает вести только в разрешённую LiveSession, без доступа к остальному хабу и без fallback в Лобби.

### Сейчас: порядок сверху вниз

1. Компактный summary `5 в голосе · 2 разговора` и action `+ Комната`.
2. Отдельный блок `Лобби · Общий разговор`: активное — компактный roster и Join; пустое — строка 40 px `Лобби · Начать разговор`.
3. Секция `Комнаты · N` с active дополнительными Rooms: стабильный порядок, текущая с marker «Вы здесь»; pinned status не поднимает пустую Room выше активной. При отсутствии дополнительных комнат пустая секция не рисуется; `+ Комната` остаётся доступной по правам.
4. Online outside rooms: компактные avatar/name tokens, не полноценная ещё одна «комната Онлайн».
5. Empty pinned: collapsed section `Закреплённые (N)`, row 40 px.
6. Temporary grace: короткая помеченная строка только пока сервер возвращает grace; после archive исчезает, текст остаётся в Group Chat.

Active row: room name слева, люди рядом кластером, справа speaking/share и Join. Нет колонок role/created date/capacity как в admin table. До 6 участников показываются компактно; остальные через `+N` с accessible списоком. Когда имён много, row может вырасти до 112 px; не растягивать по экрану каждый avatar. Create — обычная кнопка, default Temporary; pinned только при наличии права.

Вход из Сейчас открывает Full Room. После leave возврат в прежний Group view Сейчас сохраняется. Состояние «вы здесь» всегда отражает session store, даже когда пользователь просматривает другую Group.

### Люди

Search people сверху. Секции: `В разговоре`, `В сети`, `Остальные участники`. Последнее название предпочтительнее категоричного «Не в сети», если privacy не позволяет утверждать offline. Каждая строка: avatar, displayName/handle, ближайшая известная Room или status, context menu. Room badge ведёт к сведениям/Join; клик по человеку открывает mini-profile. Membership/moderation — через отдельное действие, не permanent admin columns.

Guests показываются в разрешённом room roster с пометкой `гость`. Они не увеличивают permanent member count. Если текущий Group members endpoint не возвращает guests, UI не выдумывает их; нужен отдельный scoped roster contract.

## 10. Full Room: выбор layout

**Выбран вариант C: заменить main group content area.**

Modal мешает использовать global navigation и провоцирует stack нескольких полноэкранных sheets. Отдельное окно добавляет window lifecycle и риск раздвоенного управления. Оба варианта сложнее основного сценария. Optional pop-out может быть будущей desktop-функцией, но не P1/P2 default. Создание Room следует такому же main-area переходу без формы перед входом; точный quick-create contract — в §1.

После `DRG → Зайти`:

1. Проверить текущий session context, server capability и доступ к цели.
2. Если требуется cross-context confirmation, показать его до перехода.
3. Main принимает конечную геометрию Full Room; состояние `Подключаемся к DRG`.
4. При необходимости платформа запрашивает permissions; status/retry/device choice находятся внутри той же поверхности. Нет отдельного Voople prejoin dialog и повторной кнопки Join после успешного разрешения.
5. Сервер подтверждает membership; media runtime подключается.
6. Только после readiness UI показывает активное состояние. Camera/share по умолчанию выключены.
7. Sidebar остаётся интерактивным. На background navigation появляется Mini Room того же session runtime.

Для уже настроенного mic join — одно явное действие. Первый permission prompt или блокировка браузера не считаются архитектурным «лишним экраном»: это действительное необходимое состояние.

Header: `VOICEKK / DRG`, participant count, `Чат [unread]`, `Свернуть`, `...`. Три Group tabs в Full Room не дублируются: breadcrumb группы возвращает Group Chat + Mini. При voice-only scene — компактная композиция участников, не таблица и не огромные пустые camera tiles. 2–8 человек: avatar/name cluster; больше — компактный roster с внутренним scroll. Активный говорящий подсвечивается без перестановки людей.

### Room Switcher

Название группы, постоянная строка `Лобби`, разделитель, active дополнительные rooms, collapsed empty pinned, `+ Комната`. Width 160 px. Current marker + текст `здесь`; participant count справа. Participant tree под rooms отсутствует. Hover/focus `...` у дополнительных комнат — pin/rename/archive при правах; управление не сдвигает Join hit target. У Лобби этих действий нет. Прямой возврат при скрытом switcher определён в §9.

Для 20 rooms: search появляется при >8 доступных rooms; список scroll внутри, current row можно быстро раскрыть через «Текущая». Порядок не пересортировывается при каждом count update. Up/Down перемещают focus, **не переключают комнату**; Enter/Space выполняют переход. Это list navigation, не tablist с auto-activation. Escape закрывает popup и возвращает focus к текущей Room.

При скрытом switcher header содержит `[DRG v]`; dropdown даёт тот же список и те же server actions. На mobile это bottom sheet комнат. Group Guest не видит комнаты за пределами своего scope.

## 11. Screen share

Stage заполняет всё оставшееся пространство после header/controls/опционального drawer. Исходное aspect ratio сохраняется: contain, без crop и без принудительного 16:9 для portrait/ultrawide. Letterbox — допустимая цена полного кадра; нельзя лечить его растягиванием.

Для одного stream — focus по умолчанию. Participants находятся в одной полосе 64–80 px под stage; при малой высоте заменяются compact roster button. Во время voice-only используют более заметные avatar tokens; при screen share приоритет у содержимого. Self camera preview — маленький, управляемый пользователем; не дублировать screen preview огромной плиткой.

Controls: mic, output/deafen, camera, share/stop, more, leave. У каждой media-кнопки различимы `off`, `pending`, `on`, `failed`, `unavailable`. «Разрешение 1080p» и «60 FPS» показываются как установленный publish/requested quality mode, не как измеренный delivered FPS. Actual quality при наличии измерений находится в information panel. Existing 720p30/1080p60 contract переиспользуется; недоступные device modes не обещать.

Несколько streams: один выбранный focus; остальные thumbnails/selector с автором. Не переключать focus автоматически на каждый новый stream. Сохранить последний выбранный stream, пока он существует; по его окончании выбрать оставшийся с явным status. Audio room продолжается; звук screen streams — только выбранного, остальные default muted. Возможность явно включать несколько требует отдельного mixer test и не входит в первый slice. Camera views не превращают screen-share mode в default conference grid.

Fullscreen — состояние stage в том же runtime, без повторного join. Global sidebar и drawer временно скрываются; media controls появляются по pointer/keyboard и остаются доступны при focus. Escape сначала выходит из fullscreen, не завершает звонок. После выхода восстанавливаются drawer width, selected stream и локальная навигация. В native desktop использовать существующий titlebar-safe adapter.

## 12. Group Chat во время Room

Кнопка называется `Чат`; panel header — `Чат группы · VOICEKK`. Это тот же conversation/section renderer, subscriptions, draft, read cursor, message actions и attachments. Default — последний выбранный Section этой Group, иначе Общий. Room-context filtering по умолчанию отсутствует. Позднее фильтр «Из DRG» может быть обычным search filter, но не отдельным видом истории с собственными drafts/unread.

Drawer закрыт при первом join; explicit open сохраняется для этой session. Width default 360, resize 320–480, separator управляется мышью и клавиатурой. Resize preference per device, не глобально на всех устройствах. При split stage уменьшается с сохранением ratio; при узком main panel overlay не меняет bounds лежащего под ним media stage.

На mobile panel занимает main целиком, session control band остаётся. Back/close возвращает stage, звук не прекращается. Title всегда содержит Group name; Section selector только один. В narrow drawer favorites shortcuts скрыты, dropdown содержит все Sections.

Chat unread — сумма доступных Sections этой Group, отдельно mention indicator. Если drawer открыт, читается только видимая часть выбранного Section. Закрытие возвращает focus кнопке Chat и сохраняет draft/scroll. Нельзя держать одновременно Group Chat + People drawer + Info drawer. Mini-profile поверх avatar — кратковременный anchored popover, не ещё одна постоянная колонка.

**Guest boundary.** Guest не получает Group history, Sections или composer. Room UI для гостя показывает объяснение доступного scope и account action; регистрация сама по себе не даёт membership. Текст для гостей не добавляется в обход правила через отдельный `guest-room-chat`. Если он понадобится позже, сначала отдельное решение доступа к Group conversation.

## 13. Mini Room

Появляется при навигации от активного Full Room. Это представление одной session, а не новая media connection. Default при уходе со stage — **minimal**: сохраняет максимум места переписке. Normal выбирается явным раскрытием и сохраняется per device.

```text
Normal:                         Minimal:
DRG · VOICEKK · 3   [комнаты v]  [mic off] DRG · 3 ▣ [развернуть] [выйти]
[ava] [ava] [ava]  Biba говорит
[mic] [audio] [развернуть] [выйти]
```

Normal показывает состав, одного говорящего/нескольких без jumping layout, room/group name, mic/output, share/camera indicators, expand и leave. Minimal всегда показывает mic state и leave; camera/share on имеют видимые отдельные пиктограммы. Состояние микрофона нельзя убирать до hover. Normal/minimal toggle не равно leave. `X`, если есть, обозначает только конкретное действие с tooltip; предпочтительнее явный leave icon с accessible name.

**Размещение.** Desktop — справа в зарезервированной нижней зоне main, 12 px от края. Default minimal zone 56 px, normal 128 px. Floating card визуально отделена, но composer и primary actions layout-ом располагаются выше этой зоны. Разрешено горизонтальное перемещение внутри safe zone и клавиатурное «слева/справа»; свободное перекрытие composer не поддерживается. Это уточнение floating-модели ради предсказуемого multitasking. Цена — фиксированная полоса высоты только во время свёрнутого разговора.

В экранах без composer используется та же reserved zone. При смене окна/zoom координаты clamp-ятся. Mini-player, если играет музыка, объединяется в persistent-controls stack; не накладывается поверх call dock. При разговоре музыка по умолчанию приглушается/приостанавливается согласно общей audio policy; никакой autoplay при навигации.

Mobile: minimal call band 56 px над bottom nav, в conversation — над composer; safe-area добавляется один раз shell. При keyboard open bottom nav скрывается, composer и mic band остаются над keyboard. Normal раскрывается в компактную control sheet, без permanent floating draggable окна. На Full Room Mini скрыта, чтобы не дублировать controls.

Room switch из Mini выполняется в popover и сохраняет текущую browsed страницу. На собственной Group мини-состав обновляется; в другой Group её чат не переключается. Expand всегда открывает **actual active session**, а не последнее просмотренное имя Room.

## 16. State transition map

```text
Group Chat A/B
  -- Join DRG --> Full Room connecting -- ready --> E/F
  -- denied/expired --> тот же Full Room с retry/back

E/F -- Open Chat --> G -- Close Chat --> E/F
E/F/G -- Minimize --> previous route + H
H -- Open another Group --> that Group Chat + H
H -- Open DM/Search/Profile --> destination + H
H -- Switch Room same Group --> destination + H(new session placement)
H -- Expand --> E/F(actual active session)
E/F/G/H -- Leave --> leaving -- acknowledged/reconciled --> no active session
```

| Переход | Мгновенная реакция UI | Что ожидается | Animation | Confirmation |
| --- | --- | --- | --- | --- |
| Group click / Chat↔Сейчас↔Люди | Выбран view, cached данные/skeleton | Query по необходимости | 0–120 ms | Нет |
| Join, без другой сессии | Full geometry, connecting | Permissions + server join + media readiness | 120–180 ms | Только явный Join; first permission по платформе |
| Join в другую Room той же Group | Pending marker цели; old actual room до ACK | Atomic switch + media reconciliation | 120–200 ms | Нет |
| Join в другую Group / DM→Group / Group→DM | Короткий confirmation с названием текущего и целевого разговора | После согласия authoritative switch | 120–180 ms после согласия | Да: текущий разговор закончится |
| Open/close Chat | Panel/split появляется, focus управляется | History при cache miss | 160 ms | Нет |
| Minimize | Previous route + dock | Ничего сетевого для сессии | 160 ms | Нет |
| Open Group/DM при active voice | Route меняется; dock остаётся | Данные новой поверхности | 0–120 ms | Нет; это не смена voice |
| Switch из Mini | Pending status в dock | Тот же atomic switch | 120–200 ms | Только cross-context |
| Leave | Local mic/camera/share немедленно stop; leaving state | Idempotent server leave/refresh | До 120 ms | Обычный self-leave — нет |
| End для всех / archive / delete | Описано последствие | Server authorization и mutation | После ACK | Да, destructive operation |
| Browser Back | Назад по UI; active session → Mini | Route data | 0–120 ms | Не завершает media |
| Incoming DM call во время Room | Banner с accept/decline | Explicit replacement при accept | Без захвата focus | Accept явно предупреждает о завершении текущего |

Instant относится к реакции интерфейса, не к обещанию нулевой сетевой задержки. Нельзя показывать «вы уже в DRG» до server acknowledgement. При pending показывать `Переходим в DRG…`, затем обновить actual placement. При failure проверить сервер: old session может сохраниться, новая могла успеть создаться. Отображать reconciled result, не слепой rollback label.

Same-group switch не имеет confirmation, но **camera и screen share не переносятся автоматически новой аудитории**. Перед media handoff публикации останавливаются, mic preference сохраняется; после успешного switch пользователь явно возобновляет camera/share. Inline status «Демонстрация остановлена при переходе». Это цена предсказуемой аудитории без permission matrix. При failure старую share-публикацию не возобновлять самовольно.

## 17. Session states и edge cases

| Состояние | UI и контракт |
| --- | --- |
| Idle | Нет Mini и активных mic indicators. Group Join доступен по capability |
| Prejoin | Только когда нужен invite preview/permission/recovery: состояние конечной поверхности, не обязательная промежуточная страница для каждого входа; никаких уже «подключённых» фиктивных участников |
| Joining | Pending action, один request ID, cancel/назад; поздний join после отмены компенсируется session-bound leave |
| Connected | Actual session from server, media health отдельно |
| Switching | Один pending target; повторный click не создаёт второй concurrent mutation |
| Reconnecting | Состав last-known с пометкой; paused/stale share frame обозначен; mic connection state честный; bounded retry |
| Leaving | Local tracks остановлены сразу; серверный leave retry с session ID, новый join до reconciliation не запускается |
| Failed | Причина + retry/back; draft сохраняется. Не смешивать permission denied, expired invite и network timeout |
| Kicked / access revoked | Остановить media, закрыть недоступную историю, показать доступный destination; draft не отправлять |
| Joined on another device | «Разговор открыт на другом устройстве»; explicit take-over, без двух активных senders |
| Room archived while selecting | Target недоступен, refresh list; не создавать одноимённую Room скрытно |
| Screen share ended | Remove/stale marker, другой stream либо voice scene; звонок не завершать |
| Section access revoked | Недоступные messages и cached attachments больше не показывать; draft локально сохранить для восстановления доступа, без auto-resend |
| Invite expired / session ended | Preview честно завершён; никакого автоперехода в Lobby или другую live session |
| Offline messaging | Existing cache с явным stale status; текст сохраняется, queue/retry с idempotent message ID; upload failure отдельно |

Timeout thresholds переиспользовать из существующего bounded runtime; новый UI не вводит второй набор timers. При окончательном timeout leave сохраняется pending reconciliation и явно видимое состояние; нельзя скрыть неопределённую server membership и тут же запускать новую сессию.

Reload восстанавливает route и запрашивает actual session; сохранённое UI preference не вызывает auto-join. Если сервер знает membership, а media отсутствует, показать reconnect/take-over, камера/share остаются off. Deep link на Room открывает preview; просмотр ссылки не является согласием присоединиться.

## 19. State variables и ownership

```text
NavigationState
  destination: group | dm | search | profile | secondary
  groupId? / conversationId? / sectionId?
  groupView: chat | now | people
  returnDestination

SessionState [server/runtime authoritative]
  actualSession: null | { id, kind: group|dm, groupId?, roomId? }
  status: idle|prejoin|joining|connected|switching|reconnecting|leaving|failed
  pendingTarget? + operationId + requestId
  mediaConnectionStatus
  micEnabled / outputMuted / cameraEnabled / sharePublication
  permissions / deviceCapabilities / lastError

PresentationState [UI]
  sessionPresentation: full | mini [derived absent if no session]
  miniVariant: minimal | normal
  contextPanel: null | groupChat | dmChat | details
  drawerWidth
  roomSwitcherPreference: auto | collapsed
  selectedStreamId? / fullscreen
  liveShelfCollapsedByGroup
  pinnedSectionIdsByGroup [max 2 visible shortcuts]
  pickerSearch / focusedOptionId

ConversationState [canonical cache/store]
  queryByConversationId
  unread/readCursorByConversationId
  draftByAccountAndConversationId
  scrollAnchorByConversationId
  sendQueueByMessageId / uploadStateByAttachmentId
```

`actualSession`, room participants, access и server presence не копировать в независимо обновляемые component states. `pendingTarget` отдельно от actual placement. `sessionPresentation` не владеет connected/disconnected. Layout widths и visibility выводятся из B/viewport и preference; не хранить конфликтующие booleans вроде `isRoomModalOpen`, `isFullRoomPage`, `showMini`, `isInRoom` одновременно.

Инварианты: если показан active Full Room, Mini отсутствует; при active session и non-Full destination Mini видна; drawer принадлежит active session conversation; Room Guest никогда не получает group-wide messages; новое сообщение имеет один conversation ID и один idempotency key.

## 21. Приёмка

Нужны live desktop/mobile flow и обе темы; статические wireframes не являются evidence готовности. Минимальная visual matrix: 360/390/1024/1280/1440, empty/loaded/error/offline/reconnecting, 1/3/20 rooms, 1/3/30 sections, short/long names, portrait/16:9/ultrawide share. Дополнительно Windows scale 125/150%, keyboard, reduced motion и browser font zoom 200%.

Ключевые сценарии: A→B→F→G→F→H→другая Group→DM→switch same Group→leave; DM incoming/decline/accept; cross-context cancel/confirm; guest valid/expired/revoked; lost join response; switch с active share; server state изменён другим устройством; draft/reply/upload сохранены при всех UI переходах.

Отдельный gate простоты: temporary create-and-join одним click без формы, optional rename после входа, device selection и invite без modal chain, Section creation inline, отсутствие повторного Join после permission. Для каждого основного действия записать число осознанных шагов и проверить сохранение draft/scroll/focus. Замена modal на drawer при сохранении лишних шагов не закрывает этот gate.

Architecture, native Node tests, lint, TypeScript, web/desktop production checks выполняются из checkout вне `node_modules`. В delivery matrix вносятся реальные web/desktop/responsive/state/test результаты. Этот документ сам по себе не меняет ни одной строки на «Готово».
